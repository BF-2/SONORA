一、产品使命与明确边界

产品名固定为“声序 SONORA”。面向已拥有训练好声音模型的用户，提供从一条原始音频到成品的完整制作流程。支持离线语音变声、歌曲翻唱、歌曲改词翻唱；实时变声作为独立会话扩展。默认中文，可扩展国际化。Windows 为首要支持平台，预留其他桌面系统，但不能在未验证前宣传跨平台功能一致。

新手应能通过任务、声音、预设和短试听完成创作；进阶用户应能调整素材分离、F0、音符、歌词、模型、片段、后处理和运行策略。已训练模型可直接导入，训练不是首次使用门槛。单条原始音频是常规入口，也允许直接导入干人声、分轨、MIDI、歌词和已有工程。

明确区分：音高提取估计连续 F0；音符转写给出离散音符及起止；音准评价需要参考旋律或规则；VC/SVC 改变声音，不自动生成新歌词；歌声合成 SVS 需要其自身支持的歌词、音素、旋律/音符/时长条件和模型。不能把这些能力混为一个“AI 修好”按钮。

不保证任意混音可无损分离，不保证重唱和和声全部自动分开，不保证任意训练模型互相兼容，不保证未知机器的固定毫秒延迟，不把多算法一致等同于正确。遇到能力限制时给出能继续制作的具体选项。

二、平台、架构与工程组织

固定采用 Tauri 2 桌面壳、React + TypeScript 前端、Python FastAPI 编排服务、独立 worker 推理进程、SQLite 工程元数据和内容寻址产物缓存。已有原生网页原型作为交互和视觉参考，可迁移组件，不把原型脚本直接当作生产状态管理方案。浏览器只是 UI；GPU 推理在用户本机或明确配置的远端节点运行。不要宣称仅打开网页即可运行全部大型模型。

建议仓库结构：apps/desktop 为 Tauri 工程，apps/web 为 React 编辑器，packages/contracts 为 TypeScript/Python 共享 schema 与版本，services/orchestrator 为 FastAPI/调度/工程服务，workers 下按 ffmpeg、separation、pitch、rvc、svs、dsp、realtime 分目录，engine-envs 保存引擎锁定环境，tests 存真实数据与信号验收，docs 存架构、模型导入、许可证和故障恢复文档。具体目录可以适应已有仓库，但职责不能混乱。

前端不直接拼接 shell 命令，不直接加载任意模型。Tauri 管理受限的系统文件、应用生命周期与本地连接凭据。编排服务管理工程、模型清单、依赖图、任务、缓存与事件。worker 根据固定协议处理音频；一个 worker 崩溃不应拖垮 UI 或工程数据库。

独立网页原型可真实导入、解码、播放、裁剪、绘制波形、进行明确的 Web Audio DSP 和导出配方，但这些不等于大型模型推理。生产连接只使用明确配置的服务端点、协议版本握手、能力列表和会话认证，不扫描用户本地端口。未连接、连接中、版本不匹配、模型不可用与连接断开分别显示真实状态。

所有产物具有 processing_kind=demo|decode|dsp|model_inference、input_artifact_ids、job_id、实际 worker/engine/model_hash。称为“模型转换成品”的导出必须引用成功的 model_inference 产物；没有时只允许如实命名的原音频处理版、裁剪版或工程配方。复制、重采样、转码、EQ 和移调不得冒充神经变声。关闭推理 worker 后，转换操作不能进入真实成功态。

每个引擎有独立、锁定、可诊断的环境。不能用一个全局 Python 环境依次 pip install 所有仓库。记录 Python、PyTorch、CUDA/其他加速后端、关键依赖和源码 revision。依赖安装与模型下载是显式作业，可取消、可恢复、校验哈希，不能在首次播放时悄悄执行。

SQLite 使用事务、schema_version、迁移与备份；长推理不占用长时间写事务。媒体文件与数据库分离。工程文件引用媒体哈希与相对/受控位置。缓存目录、模型目录、工程目录和导出目录可分别配置。原始素材只读保留，派生音频均另存，不原地破坏原文件。

三、阶段交付与持续推进

P0-A：完成真实导入、ffprobe 探测、FFmpeg 解码、波形/播放、非破坏裁剪、项目保存/恢复、模型导入验证、能力状态和真实导出。这是基础，不是最终完成。

P0-B：打通实际链路 FFmpeg → 分离执行器 → 独立 PitchService → RVC → 后处理/混音 → FFmpeg 导出。提供干人声跳过分离的快捷分支。使用用户有权处理的测试音频和合法取得的模型，保存真实输入输出、参数、日志、失败信息和试听位置。

P0-C：完成手动 F0/音符编辑、区间锁定、短片段试听、同源候选、对齐 A/B、分段模型、局部依赖失效、接缝检查、预设、队列、取消与恢复。P0 必须能从原始歌曲交付可播放的真实成品。

P1-A：改词工作区，先完成新导唱录制/导入 → 对齐和修音 → VC → 混回原伴奏的可靠路线；再接入真实可用的 SVS 执行器。支持缺少 SVS 时的清楚降级，不能播放原歌词却宣称已改词。

P1-B：多算法局部复核、歌词/音素与音符编辑、参数实验、区段拼选、多角色、和声、工程配方、更多兼容引擎和可选训练工作区。每个新引擎都要有 capability manifest、独立环境、真实兼容测试和许可证记录。

P2：低延迟实时会话、可选远端节点、生成式局部改写、更多研究型后端、个性化预设建议。未核验研究功能不得阻塞 P0/P1，也不能混入默认稳定链路。

按顺序推进到本次环境可完成的最远阶段，并持续维护已完成闭环。每阶段报告可运行入口、已实测内容、未实测内容和剩余原因，不用“完成 95%”代替具体状态。

四、界面信息架构

采用同一工程中的“快速完成”“精细编辑”“专家设置”三层。切换只改变信息密度，不重建工程、不清除参数、不重置播放头或选区。快速界面须提示存在高级修改，例如“当前配方含 3 项高级调整”，点击可查看差异。

顶栏：声序 SONORA、项目名、自动保存状态、撤销/重做、模式切换、任务队列、设备状态与设置。左栏六阶段：导入诊断、人声整理、音高与歌词、声音转换、混音、导出。各阶段显示未开始、处理中、可编辑、需检查、已完成、已失效等状态，不把流程锁成只能向前的向导。

中央工作画布：多轨波形与可选频谱、音高/音符、歌词/音素，共享统一时间轴。原始混音、主唱、和声、伴奏、候选和最终混音按实际存在显示，不凭空制造分离完成的轨道。选区、缩放和播放位置跨页面保留。

右栏上下文检查器：未选择时显示阶段策略；选择轨道显示处理链；选择片段显示模型和区间参数；选择音符显示音高、音分、漂移、颤音等；选择歌词显示音素、时长和冲突。参数可以搜索、按当前生效筛选，并显示来源为预设、自动建议或用户覆盖。

底部固定播放器：播放/暂停、时间、循环选区、A/B、响度匹配、独听/静音、监听输出。更改需要渲染的参数时继续播放已完成版本，显示“新版本待试听”，不要悄悄用旧版本模拟实时变化。阶段切换不无故停止播放。

设计语言简洁、易读、稳定，避免首页铺满几十个参数、隐藏含义的图标和无用仪表。颜色配合文字/图标表达状态。首次出现术语提供一句可理解说明，详解按需展开。误差、失败和缺失依赖须有下一步动作。

五、页面与键鼠操作

首页：拖入音频、选择文件、录音、打开工程、演示工程；已有项目按最近打开与任务类型浏览。导入后用户选择语音变声、歌曲翻唱、改词翻唱。实时入口进入独立会话，不强行走完整离线向导。

导入诊断页：原音播放、媒体属性、裁剪、任务与路线建议、目标模型、诊断时间点。点击风险直接跳到音频对应区间循环试听。确定性测量与启发式判断分栏呈现；“可能多人声”需要试听确认，不显示无根据的正确率。

人声整理页：原混音/主唱/和声/伴奏对照，处理链与每级旁路；显示原声、分离后以及处理后版本。拖动片段边缘裁剪，双击片段独听，框选区间运行局部处理。分离失败时可换模型或导入外部分轨，不清空已有编辑。

音高与歌词页：默认只显示最必要的两到三层。滚轮缩放，修饰键配合滚轮水平/垂直缩放；拖动音符调整时间或音高时，清晰区分当前工具，避免误改。支持框选、多选、精确数值、锁定、恢复局部、画笔和节点编辑。歌词边界可拖动并受相邻边界约束。

声音转换页：模型卡、预设、代表片段、候选列表和版本树。每个候选显示来源、模型、参数差异、渲染状态和用户备注。支持同源 A/B/C、收藏、盲听、以此为最终候选、按片段拼选。真正串联有明确的输入箭头和转换世代。

混音页：轨道推子、声像、静音/独听、实际可用效果链与发送。导出页：输出类型、格式、路径、命名、技术检查、待解决问题、工程配方选项和真实进度。导出路径冲突不会默认覆盖。

空格播放暂停，I/O 设置入出点，A/B 切换试听，Ctrl/Cmd+Z 撤销，Shift+Ctrl/Cmd+Z 重做，Esc 取消拖动/关闭当前临时工具，方向键按当前工具微调。文本输入框中禁用冲突快捷键。所有拖动功能必须有键盘或数值替代。焦点始终可见，弹层焦点可返回触发位置。

六、导入、诊断与非破坏素材管理

生产格式支持以实际 FFmpeg 构建为准；浏览器原型可用格式单独说明。导入读取时长、采样率、声道布局、编码、文件大小和解码结果，生成可复用的波形峰值金字塔，长音频不把每个采样点一次性塞入 React 状态。

诊断测量包含静音、削波/接近满幅、峰值、可用的响度与声道异常；混入伴奏、重混响、多位歌手和重唱属于启发式提示。每条提示给时间区间、证据类型、查看/试听入口和处理建议，不生成无参考的“音准 98%”“音质 92 分”。

原始音频保持不可变。裁剪、声道变换、重采样、降噪、分离和标准化产生派生节点。保留原始 sample offset、时间码、来源哈希和变换记录。中间音频采用合适的无损 PCM/浮点格式，避免每轮 MP3 编码和每一步重复限制峰值。

支持按静音、人工标记、歌词句界或固定最大长度分段。长音持续跨块时保留上下文、有效区和交叠；不得只按静音切割。所有片段保留在原时间轴的位置，空白与休止不能因自动拼接而被无意缩短。

歌曲路线推荐分离，干净语音路线跳过无关节点。用户可显式跳过，跳过表示不执行节点，不能只是隐藏界面。实际听感可能因预处理变差，任何可影响声音的步骤均支持旁路对照和恢复。

七、分离、预处理与多声部

首发采用固定版本 audio-separator 作为分离执行层，按模型能力接 MDX、VR、Demucs 或 MDXC/RoFormer 等家族；优先使用经过自有测试验证的 BS-RoFormer/MelBand RoFormer 具体权重。记录每个权重配置、采样率、stem 顺序、来源、许可与哈希，不按名称猜测输出。

UVR 作为模型生态、任务分类和验证预设参考，不在 SONORA 内嵌另一整套界面。主唱/伴奏分离不等于主唱/和声分离。“Karaoke”等模型按真实输出含义映射标签，不能只根据 Vocals/Instrumental 字段决定主唱或伴唱。

预处理提供温和预设：干净人声、有伴奏歌曲、重混响、主唱与和声重叠、近讲语音。不得默认把最强降噪、最强去混响、最强分离全部串联。每项显示用途、可能影响的气声/齿音/尾音，以及单独旁路试听。

多声部片段可独听主唱、和声与原混音，允许手动标记主旋律区、换分离器、分轨导入、保留原和声、分别变声或参考重录。说话人分段不等于人声分离；不能用 diarization 标签假装完成重叠声部分离。

处理主唱+和声造成的 F0 争夺、倍频/半频跳动和分离伪影时，先检查素材与分离，再比较算法，最后考虑模型推理设置。错误诊断不能直接建议增加训练轮次。对无法分开的区间保留“需检查”状态和人工替代路径。

实现可配置 context padding、有效区裁回、延迟对齐与 overlap-add。上游分离库的分块能力不等于成品接缝已经可靠；验证持续元音、瞬态、齿音、立体声与长混响跨边界的情况。

八、独立 PitchService 与算法矩阵

PitchService 独立于 RVC 等转换引擎，以统一数据格式输出 F0、voiced、原生分数、帧中心和算法版本。当前 RVC 官方 CLI 暴露的 F0 选项不应成为产品算法上限；实施时核验适配器是否能真实传入外部 F0，必要时在固定版本上实现受测试的接口。

默认入口仅显示“自动推荐”“快速试听”“疑难段复核”。专家面板显示算法、模型版本、音域、帧长、清浊音阈值、解码/平滑与后处理。算法目录标出已安装、可安装、缺权重、不兼容设备和测试状态。

RMVPE：作为常规歌声起点；优先分离后的主唱，必要时从原混音额外提取作参照。论文针对伴奏存在时的人声 F0，但不意味着能自动输出多人声各自旋律。
FCPE：作为快速预览或资源受限候选，以本机基准决定默认；保留 V/UV 阈值、音域和帧参数。默认不把 unvoiced 全部插值成连续音高。
torchcrepe：提供 tiny/full、周期性与解码策略，用于难段复核。静音门控独立实施，周期性不直接显示成正确概率。
Harvest、DIO + StoneMask：CPU 与干净单声部对照。遵循 WORLD 对输入采样率等要求，不能对 8 kHz 输入不作处理就声称兼容。
pYIN：离线 CPU 基线和可解释对照；用于单声部，不能作为未分离合唱的默认算法。

算法“齐全”通过插件和统一接口扩展，不意味着每次全部执行。先运行一个主算法，标记短时八度跳变、超出用户范围、低周期性、清浊音冲突和人工问题点，再对带上下文的疑难区间运行另一算法。

比较前对齐采样率、hop、帧中心和时间偏移。以 log-F0 或音分比较，不直接平均 Hz。对于半频/倍频分歧保留候选和证据，结合参考旋律与试听选择。原生分数保留自己的量纲；未做标定前禁止把各算法分数平均成统一百分比。

原生分数额外记录 native_score、score_kind、estimator_version 与 calibration_id。voiced_prob 只描述有声概率，不等于 F0 正确概率；periodicity 也不是统一音质概率。仅在明确 reference_id、有效对齐、有声交集与覆盖比例时计算音准误差。同调式但唱错旋律不能被当作音准正确。音色相似度、可懂度、技术电平和主观听感分别报告。

未知 F0 存 null 配合 voiced mask，不用 0 Hz 参与 log、音分或音准分数。用户锁定层优先，重新估计不覆盖已锁定曲线。连续 F0 与音符转写分开保存；检测算法不能凭空提供正确乐谱。

九、手动修音、旋律与时间编辑

至少保留三层：原始检测、用户接受/编辑的目标、实际渲染输出测得曲线。默认展示最必要层，颜色和图例明确，不能把目标曲线冒充输出已经达到的曲线。

支持音符中心、音分微调、八度修复、漂移、滑音入口/出口、颤音保留或减弱、起音与尾音、局部画笔、曲线节点、清浊音切换、锁定与恢复、选区复制与撤销。表现参数仅在有真实实现时启用。不要把修音简单实现为全曲吸附半音和抹平所有细节。

音高参考可为人工音符、MIDI、原唱已确认旋律或候选音阶。调性识别是建议，允许未知、不按音阶修正和临时转调。保留装饰音、蓝调音、说唱与吟唱。A4 基准可设置，默认 440 Hz。没有参考真值时只说“偏离所选音阶”或“与原唱差异”。

整体移调分清“仅主唱”和“整曲连伴奏”，显示调性关系；共振峰、音色、音高和性别标签不能合并为一个含义不明旋钮。移调修改目标层，保留原始分析结果。伴奏移调为独立 DSP 节点，使用真实已接入的算法。

优先将目标 F0 作为转换条件重新渲染；若引擎不接受外部 F0，说明替代路线为源音频修音或输出后修音，显示额外处理的可能影响。禁止静默忽略曲线。段落级时间伸缩要更新词、音素、音符和媒体的 time_map，不能只拉宽 UI 片段。

external_f0/f0_override 声明必须经过真实适配器验证。渲染清单同时记录 requested_f0_hash 和 consumed_f0_hash，接受覆盖时不能在内部隐藏地重新检测原音高并覆盖目标。对稳态有声测试片段只改变一个明显的目标音高偏移，验证输出实际响应及消耗哈希；字段存在或曲线可拖动不算接入成功。

执行器确需将目标曲线重采样到自己的帧网格时，记录该变换、前后时间基准与两个哈希，不机械要求不同网格的字节相等；验证重点是生成器实际消费了由目标曲线合法变换而来的条件，没有重新换回源检测曲线。

默认先渲染约 8–15 秒的代表或疑难乐句，用户可改长度；这是产品建议，不是强加给所有模型的硬限制。编辑试听使用同区间与可关闭的响度匹配，已完成版本与待渲染版本区分清楚。

十、歌词、对齐与改词翻唱

歌词页提供原词/原旋律与新词双栏，同步句子、字词/音节、音素、音符和时间轴。支持导入已有歌词，自动转写只作为草稿。WhisperX 可提供候选文本与时间；它的重叠语音和唱歌能力需针对素材验证，不能用来保证歌词准确。

已知文本可用固定版本 MFA 等强制对齐器，但需要合适语言模型与字典，唱歌拖音仍须人工核验。接口会变化，固定版本和 CLI/API 适配，不照旧教程猜参数。可选 GAME 用于音符转写，SOME 作为兼容备用；GAME 的 ONNX 导出不等于官方已提供完整 ONNX 推理管线。

歌词编辑支持多音字、英文重音、混合语言、发音覆盖、一字多音、连音、气口和长音。延音关系不能通过在每个音符复制同一字而重复发音。系统定位“多两个音节”“此音素模型不支持”“时长过短”等冲突，并给拆分音符、延长音节、改词或录制导唱的选项。

路线 A：录制或导入唱着新歌词的导唱 → 节奏/音高整理 → 当前已训练 VC 模型 → 原伴奏混音。只有 VC 模型时这是默认可完成路线。支持逐句打点录制、循环录制、多个 take、选择最佳句与边缘交叉淡化。

路线 B：歌词/音素 + 旋律/音符/时长 → 兼容 SVS 合成 → 可选 VC → 原伴奏混音。优先评估 DiffSinger/OpenUtau 的可控编辑接口。若目标声库已能产生目标声音，则允许直接使用，不强迫再经过一次 VC。已有 RVC 模型不能直接当 DiffSinger 声库。

SoulX-Singer 作为可选适配器：实施时固定已核验版本与权重，区分 SVS 和 SVC 两类模型；参考音色、歌词、F0/MIDI 条件的组合以实际模型能力为准。不得承诺任意语言、每个音符表现或原曲全部细节被准确复制。自动预处理和对齐的结果仍可编辑。

NNSVS/ENUNU 作为已有声库用户兼容路线；无需首版复制另一套完整编辑器。ACE-Step 1.5 之类生成式改写放实验分支，按具体 base/sft/turbo 权重核验任务，不混用旧版参数。生成式 repaint 可能改变旋律、伴奏或空间感，不宣称样本级保留。可将候选主唱重新混回原伴奏，但仍检查对齐和调性。

用户可锁定旋律、保留气口、允许拆分音符、保留句尾时长，约束彼此独立。押韵或文字建议是可选助手，不能未经选择改写歌词。修改一行仅影响相应句及必要上下文；缺少可靠旋律时允许导入 MIDI、人工修正或参考重录。

每个改词片段声明 timing_policy=locked_window|ripple_edit。默认 locked_window 保留原曲锚点与窗口长度，为音节、辅音、连音分配时长下限和允许拆分规则；不满足约束时定位冲突，不能静默挤压全部辅音或延长整首歌曲。ripple_edit 只有用户显式选择后才改变后续时间轴，同时选择并执行伴奏、标记和其他轨道的同步策略。ASR 后验只作辅助可懂度证据，不能作为歌词正确的唯一验收。

SVS 就绪探测检查声学模型、声码器、词典/音素器、语言和该架构需要的 duration/pitch predictor。表现控制取模型清单与真实适配器能力交集。只装 VC、缺声码器、缺目标音素、缺必要预测器分别有准确准备状态，只阻塞相关路线，保留导唱路径可用。

十一、模型注册、能力协商与兼容

首发 RVC 适配器以固定官方版本为主，可借鉴或接入固定版本 Applio，但不能把两者未知接口混在一起。已核验 Applio 当前强调维护而非频繁功能更新；作为版本化依赖，不承诺跟随未来路线。

模型同为 .pth 不表示兼容。导入必须识别模型家族、架构、必要配置、内容编码器与维度、采样率、说话人 ID、F0 条件、索引和声码器。缺失数据时报告未知，不以猜测结果启动推理。索引率大于零却缺索引时明确报错或要求用户显式改为无检索，不能静默归零。

模型卡显示任务、来源、许可、版本/哈希、校验、必要组件、设备与实测状态。语言、音域、风格仅在有依据时写，用户自定义标签明确区分。支持模型别名与路径迁移，身份由哈希/清单决定，不能仅用文件名匹配。

capabilities 至少包含 voice_conversion、singing_conversion、svs、external_f0、notes、phoneme_timing、reference_voice、speaker_ids/mix、formant_control、streaming、local_segment_render、training、finetuning、device/precision、cancel_mode。UI 根据真实能力启用参数和路线，不能把每个后端都画成同一套可用旋钮。

Seed-VC 作为可选参考音色/零样本转换插件，区分语音、歌声与实时权重；已核验上游于 2025-11-21 归档，代码及相应模型许可需记录，不能宣称持续活跃维护，也不能加载 RVC 权重。so-vits-svc 仅作为库存模型兼容插件；上游于 2023-11-11 归档，不能当作新歌词 TTS/SVS。

Diffusion-SVC 可作为专家插件，浅扩散要有匹配模型和条件；不是把任意两个模型串联就称精修。w-okada/voice-changer 可供流式结构参考或适配，但按已验证公开代码/版本与 edition 能力，不把所有最新二进制宣称为同一开源能力集合。

十二、多模型、多轮候选与片段编排

明确区分按人物/音轨分配模型、按时间段分配、并行候选和显式串联。默认每一轮参数尝试从同一干净源与已确认 F0 生成新分支，禁止默认把上一轮成品继续转换。

候选保存完整来源、模型版本、参数、种子、输入编辑版本和 generation_depth。真正串联由专家明确创建节点，展示上一轮输出作为输入及可能积累失真。不同架构不平均权重或参数；音频混合是独立操作，需处理时延、相位和响度。

候选源引用不可变节点/产物 ID。普通重新生成复制相同源引用，创建兄弟分支；只有显式串联命令能把上轮产物设为下一轮源。generation_depth 由依赖图计算，不信任前端填写。提交前拒绝循环依赖，缓存清理和删除候选不得破坏仍在使用的依赖。

对唱支持人物轨道与区间绑定；和声可保留原音色、单独转换或调整混音，不与主唱合并成单一 F0。人物自动识别仅建议。模型切换先检查语音边界、输出延迟与有效区，可在弱能量/休止处推荐接缝并允许人工覆盖。

接缝支持上下文渲染、交叉淡化、延迟校正和循环检查；不能仅按 UI 横坐标拼接不同模型输出。声音随模型突变不一定能靠淡化完全消除，保留未通过检查状态与重新选段功能。

分别记录算法固定延迟、padding、编解码 priming、可变 time_map 与人工对齐偏移。先依据已知延迟和锚点对齐，再做有限搜索范围的局部估计，重复节奏和长元音中的互相关峰值不直接视为真值。不确定时允许人工校正。延迟补偿不能静默删掉原有起音，监听 A/B 与导出使用同一套时间映射。

A/B 共用播放头和循环范围，可自动及手动校正偏移；响度匹配默认用于公平试听，可关闭并显示增益。支持盲听、备注、收藏和逐句拼选。选择最终候选不删除其他配方；缓存可清理，版本血缘与用户决定保留。

十三、预设、推理调优与可选训练

预设按任务、素材和能力匹配，例如自然对白、贴近原唱、保留气声、清晰主唱、和声保留、快速试听、疑难段检查。每个预设有版本、适用执行器、参数值/范围、素材前提、硬件需求和解释。简单旋钮的参数映射可展开，不能用含糊滑块隐藏任意不可追溯更改。

用户调整形成覆盖层，可比较预设差异、一项恢复或全部恢复。保存个人预设时区分通用意图与绑定具体模型的值。遇到不支持的字段明确列出；跨引擎转换需显式映射，不直接复用同名但语义不同参数。

调优分为推理设置、参数实验、训练/微调三个工作区。推理层提供执行器真实支持的检索、保护、F0、分块、精度和相关参数，说明作用与常见副作用，不伪造通用最佳值。

参数实验选择代表片段、少量变量、候选数、时间/显存预算和固定种子，保持其他条件一致。可用网格/受限搜索生成候选，但默认不同时排列几十个参数。呈现听感、技术测量、用时和显存，用户选择优先，不把单一综合分当音质真值。

训练/微调是独立可选模块：选择真实支持的架构、数据检查、分句、语言/声区覆盖、训练验证拆分、检查点试听、日志与恢复。按歌曲/录音来源划分训练验证，避免相邻切片泄漏。支持已验证执行器的检查点与参数；不承诺任何模型都有 LoRA 或相同超参数。

首发用户已训练模型的路径不受训练依赖影响。记录模型版本与训练来源说明，应用新模型后使相关推理缓存失效，原候选仍可回听和复现所需条件。

十四、混音、后处理与导出

主唱、和声、伴奏分别提供增益、声像、静音/独听及处理链；保持立体声布局。后处理至少接入实际可用的 EQ/高低切、去齿音或其真实替代、压缩、混响/延迟、限制器和响度检查。没有实现的处理器不显示为可用。

效果可旁路、排序、保存预设；显示输入与输出电平。共享混响发送有助于不同候选保持空间一致，尾音和预延迟纳入渲染长度及缓存依赖。不能把最终限制器用于隐藏上游严重削波。

stem 保存真实语义、来源与处理角色，不能仅看文件名或输出字符串判断。最终混音默认只组合选定的伴奏、人声和辅助轨，不能无意加回完整原混音造成原主唱双计。提供残留独听、相位与时长检查。导出标明 pre/post fader、pre/post FX、发送效果和母线处理位置；经过非线性母线处理后，不承诺任意独立 stems 直接相加仍逐样本等同最终混音。

Pedalboard/VST3 或 Rubber Band 可作可选后处理/变速变调层，先核验最终分发许可。独立进程不自动消除 GPL/商业许可义务。基础路径可用已验证的 FFmpeg 或其他适当 DSP 实现，不因可选插件缺失而使整个产品不可用。

导出混音成品、干/湿人声、伴奏、逐轨 stems、选区、歌词/MIDI/DS 等实际支持中间格式、工程配方和可选媒体包。导出统一时间起点、长度、采样率/位深、声道与量化策略；dither 在适当最终量化阶段处理，避免每一步重复添加。

技术检查包含削波、可用的响度和真峰值、首尾、缺口、静音和未完成片段。测量能力与算法版本明确；未实现 true peak 时不能把 sample peak 冒称 true peak。输出先写临时文件，验证后原子提交，文件名冲突默认加版本而不覆盖。

工程配方保存源哈希、模型与执行器版本、参数、歌词/F0 编辑、种子、选择的候选、时间映射和效果设置。共享时默认不附带受限模型权重；缺文件可重新链接，不能自动换同名模型。确定性依赖与随机硬件差异应在复现说明中列出。

明确区分配方可重跑、约定容差内可重现、位级一致。固定 seed 并不保证跨 GPU、驱动与精度逐样本相同。验收记录应说明属于哪一级，并保留实际依赖、设备、精度与确定性选项。

十五、实时会话与设备行为

实时模式独立使用音频进程、ring buffer、设备时钟与流式执行器。路线为话筒 → 轻量预处理 → 支持流式的 F0/VC → 输出。整曲分离、歌词识别、大型非因果模型和复杂离线多轮处理不进入实时音频回调。

系统虚拟麦克风属于独立设备集成，不是纯网页播放能力。说明需要的设备 API、驱动或虚拟音频组件与采样率/缓冲协商，只有输出能被目标软件实际选中并验证才称系统路由完成。设备变更默认安全停止或使用已经验证不会反馈的路线。

界面显示输入/输出设备、采样率、块长、lookahead、重叠、设备缓冲、dropout 和经测量的端到端延迟。使用本机回环或其他可验证方法测量，不以模型单块耗时冒充用户听到的往返延迟。

切模型先后台准备与预热，在安全边界切换；显存不足时可让用户选择短暂静音切换。不得在音频回调下载、读大文件、加载模型或等数据库。设备断开时安全停止或按已选策略旁路，避免无限重启与反馈啸叫。

实时录制保存输入、输出、时码与参数，结束后可转入离线工程精修。语音默认不吸附音乐音阶；唱歌实时修音明确显示调式与延迟代价。不同硬件和驱动测试结果单独记录。

十六、核心数据 schema

使用 JSON Schema 或等价的共享 schema 生成/校验 TypeScript 与 Python 类型。所有实体有稳定 id、schema_version、revision、创建/修改时间。工程时间不得仅靠浮点秒累加；用原始 sample offset 和明确 rational timebase 或精确 tick 表示，显示层再转换成秒。

整数时间契约必须落实到 API、数据库和 worker 输出：每个产物记录 sample_rate、sample_count、source_offset、frame_hop、frame_center_offset、valid_range 与可组合 time_map。重采样、裁剪、padding、延迟和变速逐步组合映射；F0 插值不能跨清浊音边界盲插。用 44.1k→16k→48k、非整秒裁剪和长音频的事件锚点自动验证，不以肉眼看播放头替代。

Project：id、name、schema_version、asset_refs、track_refs、graph、active_revision、history_head、device_preferences、preset_refs、exports。

PitchTrack：source_hash、estimator/version、sr、hop、frame_time_offset、f0_hz[]、voiced[]、native_score[]、score_kind、calibration_id、time_map、target_edit_refs、locked_regions。
Note：id、start/end、pitch_midi_float、reference_source、confidence_state、phoneme_refs、slur_relation。
Phoneme/LyricUnit：text、language、pronunciation、start/end、note_ids、is_breath、is_slur、alignment_source、manual_override、timing_policy、minimum_duration、anchor_refs。
Edit：id、base_revision、target、range、operation、parameters、locked、actor、undo_inverse/reference。

F0 长数组、波形金字塔和大音频不必直接塞 SQLite 行，可作为带类型头与校验的产物保存，数据库引用。schema 迁移先备份并可恢复，未知未来版本应拒绝破坏性写入。

十七、引擎接口、API 与事件

每个执行器至少实现 probe_environment、probe_model、describe_capabilities、estimate、prepare、render、cancel、release。probe 不应以不受约束地加载任意序列化文件作为唯一识别方法。estimate 返回区间与依据，不知道则标未知。

render 输入包括 job id、不可变输入产物、请求范围与上下文、参数、模型引用、时间基准、进度通道与取消令牌。输出必须给产物引用、采样率、样本数、声道、latency_samples、valid_range、time_map、告警和实际生效参数。模型忽略参数应是错误或显式告警，不能当成功。

API 至少涵盖工程创建/打开/保存，导入与重新链接，模型探测/注册，能力与预设查询，设置参数，F0/歌词/音符编辑，创建候选，计划/运行节点，取消/恢复作业，比较/播放产物，导出媒体和配方。请求含 project revision 与幂等键，避免双击导致重复大任务或覆盖新编辑。

通过 SSE/WebSocket 等实际选定的机制发送事件：job queued、node started/progress/artifact committed、warning、blocked、failed、cancelled、completed。事件有递增序号，断线后能从最后确认位置补取。前端重连不重新提交同一作业。

进度区分字节/帧/块/节点等真实依据；未知阶段不编造线性百分比。ETA 根据短样本和运行实测更新，显示合理范围。用户在运行中改参数时创建新 revision/任务，不改写已经开始作业的不可变输入快照。

十八、缓存、局部重跑与边缘范围

内容寻址缓存键包含源哈希、输入产物哈希、请求区间、实际上下文范围、声道布局、采样率和重采样策略、编辑/F0/歌词/音素/音符 hash、执行器代码 revision、模型/配置/索引/编码器/声码器哈希、全部生效参数、seed、精度和影响结果的运行配置。

每个节点声明依赖区间扩展规则。两秒编辑可能需要重算带前后文、overlap 与接缝的更大区间。分离器或生成模型若依赖整段上下文、全局归一化或不支持 local_segment_render，则诚实重跑整节点。不能只改 UI 两秒却复用已经不再正确的边缘结果。

节点的局部策略包含最小上下文、感受野已知/未知、有效区裁回、尾音长度、状态依赖、全局统计依赖及局部与整段结果的容差。单独渲染区间可能与整段因条件不同而不完全相同，只有经过测试的模式才能提供无缝局部缓存保证。

混响/延迟尾音、压缩器状态、线性相位滤镜前后振铃、lookahead、整曲响度归一化与全局增益变化都可能扩大依赖范围。时间伸缩改变后续位置，歌词与下游 time_map 必须重新计算相关区段。算法感受野未知时选择保守范围并说明。

只改输出文件编码不重跑模型；只改混音推子通常重算混音与导出；只改一句歌词重算该句生成及上下文、接缝和受影响混音；换模型不可复用旧转换产物。用户锁定的手修数据独立于分析缓存，缓存清理不能丢掉编辑。

缓存写入先临时产物、校验、事务提交，再标成功。半截文件不能命中。缓存清理显示预计空间、当前工程引用和可重建性，避免删除唯一媒体。重启恢复检查版本和校验；同名权重变更哈希立即使相关结果失效。

十九、硬件探测、性能与资源预算

首启动探测 OS、CPU、RAM、可用设备与实际运行库，随后运行可取消的小样本测试。不能根据 NVIDIA/AMD/Intel/Apple 名字直接假定所有算子可用。audio-separator 的后端矩阵和实验性能力须按锁定版本逐模型验证；DirectML 支持不等于所有架构都能 GPU 推理。

性能档案记录设备、驱动/运行库、引擎/模型、精度、片段长度、采样率、批量/分块、冷启动和热启动耗时、峰值内存/显存、失败与输出有效性。以这些数据推荐快速/平衡/质量预设，不编造统一 4GB/8GB 可运行保证。

先用代表短片段估算整曲时间和资源范围，再让用户选择整曲。CPU 备用必须真实被该执行器支持；不支持时明确说不支持。显存不足先释放不用模型，降低批量或分块，切换受支持精度/设备，修改写入配方，重试次数有上限。

默认重 GPU 作业按预算排队；只有实测显存与资源余量允许才并行。试听片段可优先于整曲任务，不能导致正在提交的缓存损坏。UI 波形和音频回调不被 Python 阻塞任务拖住。远端只在用户显式选择节点后上传，GPU 不足不自动上云。

二十、失败恢复、工程历史与设置

作业状态：queued、preparing、running、blocked、succeeded、failed、cancelled；节点状态与工程“需检查”状态分开。失败分类含输入缺失、解码失败、模型不兼容、缺依赖、显存/内存不足、设备断开、推理异常、输出校验失败、磁盘空间不足。

错误提示展示发生阶段、可保留成果和可执行恢复动作，例如重新链接、补配置、换兼容模型、减小分块、释放缓存、重试或导出诊断。日志保留技术细节，用户主流程不堆栈追踪。不得把部分完成标成整曲成功。

取消尽快停止可取消阶段，不能安全取消的外部进程按适配器规则处理；保留已提交成果，不导出半截成品。崩溃重启后恢复工程与已提交节点，损坏临时文件可清理。编辑历史与产物版本一致，撤销歌词/音高应恢复对应依赖状态及旧产物引用。

设置包含音频设备、模型/缓存/导出目录、硬件配置、最大并发/缓存预算、默认采样率策略、备份、主题、字体缩放、高对比、减少动效、快捷键、隐私/远端、引擎管理与日志。设置有范围：全局、工程、轨道、片段；UI 显示当前参数来源，避免被隐藏覆盖。

二十一、本地安全、来源与许可证

本地服务默认回环地址，会话随机凭据与 Origin 校验，限制可读写路径和上传范围，不能默认全网卡无认证服务。远端节点使用明确配对、加密传输和任务归属。命令参数用结构化调用；文件名、模型名和歌词不拼成 shell。

模型与压缩包导入检查路径穿越、大小/数量限制、哈希和必要文件。优先安全格式或适用的受限加载方式；未知 pickle 不在主服务无约束反序列化。进程隔离提高稳定性，但不能被描述为完整安全沙箱。确需不可信加载时设计操作系统约束与清楚的信任边界。

禁止模型加载失败后自动退回 weights_only=False 或其他任意 pickle 执行方式。旧权重确需兼容时，使用具备实际文件系统、网络和进程权限边界的转换/执行环境，并准确展示来源；普通同权限子进程不是安全沙箱，SHA-256 只证明完整性而非作者可信。架构探测不得为了识别模型先完整执行反序列化；不支持结构就返回可解释失败。

工程、预设、歌词、模型清单与媒体同样验证 schema、大小、递归深度和路径作用域。处理压缩包符号链接逃逸、解压炸弹、危险 YAML 标签和远程 playlist；FFmpeg 只用允许的协议和资源限制，不隐式跟随远程引用。歌词和模型名按文本安全渲染，插件清单不能任意执行安装命令。

记录代码、模型权重、内容编码器、声码器、第三方库和素材各自来源与许可。RVC/Applio/audio-separator 等代码许可不能自动覆盖所有第三方 checkpoint；同一仓库的不同模型也逐一核验。不要把组合软件统一标作 MIT。

已核验参考边界：Seed-VC 为 GPL 系列许可，so-vits-svc 为 AGPL；FFmpeg 实际许可受构建开关影响；Pedalboard 和 Rubber Band 有需要评估的 GPL/商业分发条件。独立进程或插件划分不自动免除义务。构建时输出实际 SBOM、版权声明、依赖版本、FFmpeg 编译信息和再分发清单。

默认让用户导入有权使用的权重，按获准的方式下载/分发。未知许可记“未确认”，不伪造商用保证。许可检查不能变成每次制作都重复弹出的无关阻断，放在安装/模型管理和发布清单中，具体能力风险在需要时说明。

模型的代码/权重许可与输入歌曲、声音身份和素材的使用权限分别记录，不因模型可用就自动认定素材也可再分发。发布包逐项列出内置资产的再分发依据；无法确认的权重不自动放进安装包。

二十二、验收测试与真实质量验证

测试覆盖实际用户路径、信号正确性、数据恢复和安全边界，不只验证按钮存在。保存小型可再分发或自生成的技术测试音频；音质测试使用有权处理的真实素材。技术合成信号用于时序/采样/峰值检验，不能替代真实歌声听感。

必须验收：
1. 已训练兼容模型+干净语音可真实变声导出，无训练前置。
2. 一条含伴奏歌曲完成真实分离、F0、RVC、混音、导出，所有产物可追溯。
3. 主唱+和声样本给出区间提示与检查路径，不生成虚假音准评分。
4. 快速/精细/专家切换保留工程、播放头、选区、参数和历史。
5. F0 重新检测不覆盖锁定人工编辑，静音与清音不无条件插成有声。
6. 倍频误判局部修复后按实际上下文重跑，未受影响区域复用正确产物。
7. 外部 F0 不支持时显示真实替代路线，不能假成功。
8. 新候选默认同源；显式串联的 generation_depth 和输入正确。
9. 多模型接缝时间正确，无意外缺口、重复字或截断；A/B 同位置可验证。
10. 新词参考导唱路线真实更换歌词；缺 SVS 模型时不冒充已合成。
11. 多音字、英文混唱、一字多音和时长冲突能定位、编辑和保存。
12. 上游局部变化、全局响度变化、混响尾音和时间伸缩各自失效范围正确。
13. 模型哈希变动不命中旧缓存；部分文件与取消产物不被当成功。
14. 崩溃、重启、缺文件、磁盘满、OOM 和设备断开可恢复或准确提示。
15. 混音与 stems 的起点、长度、采样率和声道说明一致。
16. 输出编码、峰值、响度或 true peak 使用实际实现的测量，未测不宣称通过。
17. 键盘可完成导入、试听、参数修改、候选选择和导出；无焦点陷阱。
18. 长音频波形与编辑保持响应，试听优先队列不会破坏整曲作业。
19. 未认证请求、越界路径和恶意压缩路径不能控制服务或越界写入。
20. 工程配方再导入能恢复编辑，缺失模型可准确重新链接，不静默换模型。
21. 关闭模型 worker 后不能产生真实转换成功态；转换成品的产物血缘可追踪到模型调用。
22. 外部 F0 测试验证 requested/consumed 哈希和可测输出响应，不只检查 API 字段。
23. locked_window 新词保持整曲长度与后续锚点；ripple_edit 明确执行全轨同步策略。
24. 恶意 pickle 不执行测试标记动作，加载失败不自动不安全降级；媒体远程引用不隐式访问。
25. stems 与 bus 的导出语义明确，最终混音没有无意加回原混音或双计主唱。

音质验收用固定片段、同区间、对齐和响度匹配，检查低音/高音、长音、颤音、滑音、气声、清辅音、重唱、分块接缝和尾音。客观指标标明参考与含义；避免把单个谱差、相似度或 F0 误差当最终主观质量。

每个引擎出具实测表：运行环境、版本、输入、参数、输出、用时/资源、已通过与失败。未在本机运行的能力写未实测。演示工程与测试桩持续标记，不能出现在真实导出路径冒充完成的模型输出。

二十三、最终交付

交付完整源码与锁定依赖、Windows 开发启动/打包步骤、真实可运行应用、模型导入与环境管理、示例工程、已通过验收记录、架构与操作流程图、API/schema、许可证与依赖清单、故障恢复文档和已知限制。

安装体验优先少步骤。可以将桌面壳、核心运行时和按需引擎分开交付，但要解释首次安装大小、下载内容和离线准备；不要承诺一个很小的 EXE 内装下所有大型模型。保持用户无需全局安装一堆互相冲突的环境。

最后报告真实完成的路径、如何启动和导入模型、测试了什么、哪些功能未实测或被资源阻塞、可继续的位置。继续保持代码和工程可运行，不以宣传性功能列表代替交付。
