## 覆盖的制作行为

| 场景 | 必须保持的结果 |
| --- | --- |
| 只修改主唱的一个参数 | 深合并该声部参数，保留其模型与选择，也保留整个和声配置 |
| 清空一个声部的候选选择 | 显式 `null` 只清空当前声部，原声回退不影响另一声部 |
| 尝试跨声部采用候选 | 拒绝请求，项目版本和路由保持不变 |
| 全局工作区已有旧模型/F0 编辑 | 独立声部使用自己的参数与空编辑，不隐式继承旧的全局设置 |
| 改变声部模式或候选 | 仅使混音/导出失效，不要求重新执行未改变的模型推理 |
| 渲染期间修改同一或另一声部 | 保留更新后的设置；另一声部的修改不阻止本声部采用仍有效的结果 |
| 主唱提交后取消，或和声随后失败 | 主唱产物与候选保留，和声原有绑定保持可用 |
| 分离期间编辑已有声部 | 新分离结果可保留供检查，不能覆盖更新后的绑定与人工编辑 |
| 两条声部音频字节完全相同 | 配方恢复仍保留两种声部语义与各自控制 |
| 素材暂缺后再次保存配方 | 未解决的声部绑定不会丢失；按哈希重新链接后恢复其参数 |
| 同内容被重新导入为新素材 ID | 缓存通过显式元数据别名关联当前输入；原推理生产者、文件哈希和路径保持真实 |
| 只渲染一段短试听 | 不自动替换整段声部，也不能通过采用操作静默截掉其余演唱 |
| 已选转换候选缺失 | 选中关系被清除后正确恢复原声回退，同时保留其他仍有效轨道的人工静音 |
| 相同缓存结果多次重跑 | 每个声部只有一个选中轨道发声，重复候选不叠加音量 |
| 修改声部后保存/恢复配方 | 已过期的混音仍需重建，不能在恢复后重新被视作当前成品 |

检查仅证明这些输入与状态下的行为。并不证明任意歌曲都能准确分出主唱与和声，也不表示剩余声部完全没有串音、残留伴奏或分离伪影。
