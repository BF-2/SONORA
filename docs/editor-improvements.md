# 音高编辑、分离调节与版本归档

2026-10-31 完成源码与浏览器版构建。启动入口仍为根目录 `启动声序.bat`。已运行的后端需要正常关闭后重新启动；只刷新旧服务页面不能加载新增 API。本轮没有重建旧 Tauri EXE。

## 调研依据与取舍

- [WaveSurfer 官方项目](https://github.com/katspaugh/wavesurfer.js) 提供时间轴、缩放和选区交互参考。本项目沿用原 Canvas 与播放器，添加可见的时间尺、窗口和定位控件，避免同时引入第二套音频播放状态。
- [audio-separator 官方文档](https://github.com/nomadkaraoke/python-audio-separator) 与[固定版本模型目录](https://github.com/nomadkaraoke/python-audio-separator/blob/v0.44.2/audio_separator/models.json)用于确认已有执行器和可兼容的 Karaoke 模型；[官方模型映射说明](https://github.com/nomadkaraoke/python-audio-separator/blob/main/docs/deton24-model-mapping-and-ensemble-guide.md)列出了 Gabox Karaoke V2。
- 本机 `audio-separator 0.44.2` 的 `mdxc_separator.py:298–307` 将 RoFormer `overlap` 用作步进秒数，并取 `min(step, chunk_size)`。因此页面标注“窗口步进（秒）”，不把它误称为重叠次数。减小步进才增加重叠计算。该实现的 RoFormer 分支没有使用 batch_size，因此不增加无效的批量参数。
- [Music-Source-Separation-Training 中关于 TTA 的说明](https://github.com/ZFTurbo/Music-Source-Separation-Training/issues/157)介绍了原始、换声道、反相后的多次估计。这里在项目适配器内完成三次估计、逆变换和平均。它是可选的推理方式，不能保证每段音频都优于单次推理。
- [模型训练项目发布说明](https://github.com/ZFTurbo/Music-Source-Separation-Training/releases)也区分通用 vocals 与更细的声部。继续保留两级流程：原曲→混合人声/伴奏；混合干人声→主唱组/和声组。不能把通用人声模型当作逐人分离算法。

## 音高编辑

“音高与歌词”中的时间轴提供放大/缩小、全曲、缩放到选区、定位播放头、窗口起点与长度、平移滑块、纵向音域及适配音域。时间显示到毫秒；实际编辑精度受检测帧长约束，本机常用 RMVPE 为 10 ms。视窗按工程/声部保存，缩放不占用撤销历史。

选择工具可以拖动框选；点击时间尺定位。连续绘制对经过的原生帧插值，单笔分组显示、一次提交，可整笔撤销、重做、解除锁定或恢复。落在源音频之外的绘制不会被错误夹到首尾帧。已锁定区域会明确提示先解除锁定。解除锁定会清除旧绝对快照，重新锁定时按当前目标重新冻结。

绿色目标由后端与实际转换共享的 `apply_target_parameters` 生成，包含滤波、自动音准、整体移调、人工音符、手工编辑和绝对锁定；不再由前端维护另一份近似计算。蓝灰色为原检测，橙色为选中输出的真实复测。使用旧检测时明确显示“旧检测上的目标预览”。

直接使用“生成编辑后的选区试听”，随后切换 A 原始人声 / B 转换结果并播放。新候选会自动成为当前试听候选；“复测输出音高”可显示实际输出曲线。目标变化后，旧 B 音频标记为历史音频，必须重新生成才能听到变化。F0 是转换条件，不保证最终波形的检测音高逐帧精确一致。

## 分离模型与参数

人声/伴奏开放现有两套模型；主唱/和声保留 aufr33 & viperx，并新增 **MelBand RoFormer Karaoke V2 · Gabox**。新增 checkpoint 为 913,090,472 字节，下载和配置均按 GitHub release 提供的 SHA-256 校验；原权重没有修改。再准备命令：

```powershell
.venv\Scripts\python.exe scripts\prepare_harmony_gabox.py --download
```

每级独立保存 `separation_settings` / `harmony_settings`，提供快速、均衡、精细对照参数起点，也可手动调节：

| 设置 | 含义 |
| --- | --- |
| 单次 / 三次增强平均 | 后者串行运行原声、换声道、反相，逆变换后平均，约需三倍推理量 |
| 上下文窗口 64–1024 帧 | 决定单窗口长度；更大需要更多显存，不保证更好 |
| 窗口步进 0.25–16 秒 | 越小重叠越密；超过窗口长度时按窗口长度处理 |
| 分配强度 0.5–1.5 | 1.0 为模型原估计，调整目标轨的分配，互补轨同步变化；不是去串音质量分数 |
| CPU 线程 1–8 / 运行设备 | 控制本地执行资源，设备选择与现有全局设置兼容 |

始终保持 `互补轨 = 输入 - 目标估计`，使用浮点 WAV，避免逐轨归一化破坏重建。模型、配置、适配器代码和全部有效参数均参与缓存键。渲染不会下载模型；权重没有随可再分发安装包打包。

## 版本归档

“声音转换 → 候选与版本”提供当前/归档分页、名称/备注搜索、手动归档与恢复，以及“立即整理旧版本”。默认在新候选成功提交后，对同来源、同声部分组保留最近两条；新生成的整个多版本对比批次一起保留。

收藏、恢复保留、当前采用、未静音/独奏轨、拼选引用、A/B 引用受保护，因此当前列表可能多于两条。归档不删除媒体和血缘，也不改变混音。恢复后的版本会保留，直到手动再归档。可以关闭自动归档；不会在打开旧工程、恢复配方或失败/取消任务时自动清理。
