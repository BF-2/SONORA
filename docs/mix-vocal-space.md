# 混音页：人声厚度修复与 C 空间

在「成品与混音」中点击混音台的声部名称，右侧可以应用 C 方案。对带原人声与 F0 来源的转换候选，方案加入人声厚度修复和 C 空间，并明确停用原房间混响；其他轨道可以单独使用 C 空间。

- 厚度修复 0–150%：按当前候选及其原人声的频带差异计算低中频补偿，结合保存的目标 F0 和强弱包络。100% 是 test7 实验的基准策略，不会混回原歌手声音。数据驱动的锚点经过收缩、上下限约束；没有启用共振峰锐化或次谐波合成。0% 原样旁路。
- C 空间 0–350%：100 / 200 / 316% 对应 C / C+ / C++。湿声支路基准 RMS 为干声的 −21 dB，强度线性缩放湿声幅度。最终采用整轨恒定 RMS 补偿，避免简单增大音量。此补偿不是 LUFS 等响认证。
- 衰减 0.1–3 秒、宽度 0–1.5；更多参数包含预延迟、湿声低切、高频截止和演唱时压低湿声。宽度只影响湿声；干声的原始左右声道保留。
- 效果按界面显示顺序执行，可上下移动、旁路和删除。拖动滑块时暂存数值，松开后提交并更新试听。

新添加的房间混响使用 `diffuse-v1`：左右不同的早期反射、密集指数尾声、湿声滤波和声道联动压低。它取代“仅靠稀疏延迟制造房间感”的新建默认值。已保存、没有算法标记的 `reverb` 仍使用 `legacy`，可在页面明确点击「升级为立体声混响」。不会静默改变旧工程。

## 渲染与来源

所有效果先对完整源轨计算，再按时间轴偏移并截取试听区间，因此短预览具有正确的前序反射与相同控制曲线。中间结果在 `runtime/cache/mix-effects/` 按输入、参考与 F0 哈希、增益、声像、效果顺序及算法版本缓存；更改设置会产生新的结果。进程可随任务取消，中间临时文件清理。混响尾声遵循项目的原时长裁切规则，不自动延长歌曲。

厚度修复对大谱矩阵分块计算，保存原长度和长静音内部。以生成记录重建包含移调、手工修改与锁定区的目标 F0，并核对其哈希，不会把未修改的检测曲线误当成生成目标。原参考、目标 F0 和生成声必须可追溯；没有可靠来源的导入音频、拼接音频不会被假装成可参考修复，只能使用独立空间效果。声部输出/推子后导出、独立监听、选区试听和完整混音共享同一处理链。

核心依赖新增 `scipy==1.15.3`，仅安装到 SONORA 核心 `.venv`；RVC、分离与音高模型运行环境没有更新。

## 验证

`tests/test_mix_space.py` 验证零强度精确旁路、强度与侧声道能量单调关系、反相输入保留、静音、低中频补偿、处理顺序、预览/完整渲染同区间一致、参数原子拒绝、旧算法兼容和生成目标 F0 核验。相关混音/工程回归共 43 项。

`scripts/verify_mix_space.py` 使用 `runtime/mix-space-qa/data` 独立数据库和 test7 素材副本，验证实际页面保存/刷新/排序/旁路，经典与柔和主题、真实混音试听以及 127.573333 秒全长渲染。未修改生产 test7 的效果或成品。

本次工作是混音后处理；RVC 立体声转换原型另在独立实验目录验证，不改变正式生成引擎的单声道行为。
