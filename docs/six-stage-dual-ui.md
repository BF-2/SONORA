# 六阶段双 UI 与整曲验收

2026-11-01

## 界面与操作归属

正式编辑器沿用六阶段顺序，即导入诊断、人声整理、音高与歌词、声音转换、混音、导出。顶栏的经典 UI 和柔和 UI 共用同一项目、播放器、选区与专业参数，柔和界面的配色与圆润层次参考 `2494a5a`。

项目库集中处理项目新建、重命名、搜索及切换。项目卡显示音轨数量、完整生成数量、导出次数和保存的阶段。切换前提交当前编辑，项目中的声部、模型、曲线和版本按项目 ID 隔离。

各配置的主要位置如下。

| 阶段 | 配置与操作 |
| --- | --- |
| 导入诊断 | 制作任务、素材角色、文件导入与媒体检查 |
| 人声整理 | 一阶段分离模型和参数、二阶段声部分离模型和参数、两类分离结果的采用与归档 |
| 音高与歌词 | 独立声部的检测算法、音域与门限、曲线编辑、锁定、选区试听与输出复测 |
| 声音转换 | 当前声部的模型实验、Epoch、索引、检索比例、保护、音量包络、目标平滑及其他专业参数 |
| 混音 | 当前采用轨道的增益、声像、偏移、静音与独奏、滤波、混响、延迟和限制器 |
| 导出 | 具体产物、格式、位深、文件名、测量与下载 |

导入页的重复模型编辑和跨阶段自动执行入口已精简。工作流条显示状态和依赖，执行按钮归属各阶段内容区。专业模式继续显示支持参数的范围、生效条件和诊断信息。

转换页的独立片段生成、片段参数实验、片段模型绑定和局部拼选入口已移除。完整版本生成明确忽略历史片段绑定。音高页继续提供局部修改和选区试听，历史试听归入“音高试听记录”。已有产物与历史数据继续可读。

## 多音轨与多次生成

每次成功的一阶段分离形成一组人声和伴奏，每次成功的二阶段分离形成一组主唱和和声。每组显示实际模型、时间、参数、输出时长及来源。

采用二阶段旧结果时会同时恢复对应的一阶段输入。每组的声部编辑快照随切换保存，重新采用时可恢复。当前采用或正在混音使用的结果有归档保护，归档与恢复操作保留音频文件。

转换版本按完整人声、主唱和和声分别管理，并区分完整版本、音高试听记录和归档记录。每条显示混音采用状态、试听状态、模型 Epoch、来源与实际参数。原有收藏、自动归档、盲听和 A/B 比较继续可用。

混音台默认显示制作中的音轨，“显示历史音轨”可展开历史结果。导出选择器使用分离批次、完整候选名或混音版本编号来区分同名媒体文件。

## 实测发现与修复

- Beta6x 原配置使用 `vocals/other`，资源登记使用了另一模型的原生名称。已修正本机登记及资源准备脚本，重跑完整分离成功。
- 从已有曲线声部切换到尚未检测的声部，会在异步刷新期间访问旧曲线。现按产物 ID 绑定曲线数据，并按项目、声部和分析产物重建编辑视图。
- 声部执行会继承公共设备参数，工作流判断原先没有使用同样的继承规则。现将界面显示与后端判断统一到实际执行设置。
- 分离自动更新输入后，旧 pipeline 将内部来源变更误认为用户修改。已保留真实用户编辑保护，同时识别 pipeline 自身的输入更新。
- 项目库现在跟随保存后的项目状态刷新名称、计数与阶段，首次加载完成后才启用阶段导航。
- 窄屏保留唯一的任务队列入口，桌面和窄屏均可切换经典与柔和 UI。

## 验收证据

139 项回归通过。两个跳过项分别需要 Windows 符号链接权限及测试解释器中的可选 `noisereduce` 依赖。真实分离与 RVC 运行在各自现有执行环境中完成。

两套 UI 在 1440 和 390 像素视口下检查通过，文档没有横向溢出，六阶段与参数值保持一致。快速往返切换主唱和和声的最终检查没有新增 JavaScript 异常。

证据集中在 `apps/web/qa/six-stage/`，包括分离采样检查、完整转换检查、F0 消费校验、项目切换比对、UI 视口检查、最终文件解析及回归日志。
