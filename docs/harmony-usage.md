# 主唱与和声分别转换

本次更新接通的是两类声部组：模型估计的主唱与背景人声。背景组可能包含多个和声、双轨或残留伴奏，不能据此识别每一位歌手。输入声部重叠、混响与唱法会影响分离，最终仍需独听检查。

本轮按照用户要求不做 Windows 桌面 UI 测试。界面流程在浏览器验证，原生部分只执行 CLI 编译；新版文件为 `apps/desktop/target/release/sonora-harmony.exe`，启动脚本优先选择它，保留当前旧版进程。

## 使用流程

1. 导入原曲，在 **人声整理** 完成“人声/伴奏分离”。如果已有混合干人声，可直接以“人声”导入。
2. 在同页的第二步选择明确的混合人声输入，运行 **主唱/和声分离**。原混音不会自动被当作干人声。也可直接导入外部分好的主唱和和声，跳过模型分离。
3. 在 **声音转换** 分别选择主唱和和声的模型。每一轨可设置为“转换”“保留原声”“静音”。模型、移调、音高算法、检索率、手工曲线、人工音符与最终候选相互独立。
4. 单独运行当前声部，或运行 **分别转换两声部并混音**。重 GPU 操作串行执行，每个声部先提取自己的 F0，再交给它自己的 RVC 模型。某一轨失败或取消不会丢掉另一轨已经提交的结果。
5. 短试听仅用于循环与 A/B，不自动替换完整声部。只有覆盖整条输入的候选才能采用到整曲混音，避免短试听截断剩余演唱。
6. 混音由选定的主唱、和声与伴奏组成。完整原混音、合并人声及未采用的旧候选保持静音。选择一轨候选不会覆盖另一轨。
7. 检查推子与峰值，重新混音后导出。改变采用候选/原声/静音会使旧混音失效；不会把旧混音当作新设置的成品直接导出。超过0 dBFS的浮点中间文件不会隐式削波成整数WAV，可先降低推子或保留浮点格式。

每次编辑自动保存，模式切换只改变当前查看的声部。双声部绑定与手工编辑会进入工程配方；恢复时按来源和声部同时关联素材，不因两轨PCM字节相同就合并身份。旧完整人声拼选/参数实验仍留在原单声部流程，当前不允许覆盖双声部混音。

## 声音质量边界

一个由两条已知自然录制人声构成的受控混合显示有效分组，结果记录在 `engine-envs/harmony/controlled-real-projection.json`。另一个SVS生成信号混合未被有效分开，失败记录保留在 `controlled-projection.json`。不把技术重构正确、单个受控样本或输出非空当作所有歌曲都能干净分离的保证。

和声组存在多个同时发声的旋律时，单条F0主要描述检测到的主导音高。当前提供独立声部处理和保留原和声选项，未承诺把任意合唱拆成每位歌手的单独旋律。建议先循环试听高音、长音、和声进入和退出处，再决定是否转换背景组。

模型来源、权重/配置哈希、专用下载器、CPU验证及电平修复详见 `docs/harmony-engine.md`；状态与恢复回归详见 `docs/harmony-review.md`。
